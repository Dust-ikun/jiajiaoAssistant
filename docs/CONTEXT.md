## 1. 一句话

把微信家教群里整段复制的聊天记录粘进来，自动剥离噪声、按编号拆单、抽取字段、折算时薪、判定「我接不接得了」，最后按通勤近不近、价钱值不值、新不新排序 —— 取代在微信里反复翻聊天记录找单。

---

## 2. 已确认的产品决策（不可推翻，要改先问）

| # | 项 | 决策 |
|---|---|---|
| 1 | 采集 | **只做粘贴导入**。剪贴板监听、文件导入列为后续可选项。**不做微信 hook 实现**，只预留 `POST /api/import` 这一个 HTTP 入口 |
| 2 | 形态 | 桌面应用（Electron 壳），但业务逻辑全在本地 HTTP 服务；浏览器直连 8787 功能等价 |
| 3 | 多人 | 为「同学一起用」预留：出发点与通勤缓存**跨用户复用**，缓存键不绑用户 |
| 4 | 科目 | 全科通用，不做单科深挖 |
| 5 | 时效 | **必须用消息发送时间**，不能用导入时间 |
| 6 | 通勤 | 高德**公交路径规划**（地铁公交），要能看**多种换乘方案**；预留 provider 接口便于后续加驾车/其他地图 |
| 7 | 出发点 | 独立 `origins` 表，支持多个、可设默认 |
| 8 | 默认排序 | **通勤时间最短优先** |
| 9 | 复制方式 | 用户 Ctrl+A 只能选中聊天记录的一小块，会**分多次复制**同一段 → 必须支持字段级增量补全 |
| 10 | 筛选重点 | **排除优先**。硬门槛（学历/性别/身份）自动判定，比每次手动筛更省时间 |
| 11 | 隐私 | DB 与缓存全本地；**地址会发高德，用户已明确不介意** |

## 4. 家教单术语表（新会话最容易理解错的部分）

| 词 | 含义 |
|---|---|
| **信息费** | 中介收的佣金，通常按课时费的倍数收。**与用户收入无关**，不参与筛选 |
| **试课** | 第一次课，可能不收费或半价。「试课日期」是可选信息 |
| **一对一 / 一对二** | 学生人数，不是老师人数 |
| **双胞胎** | 学生数 = 2 |
| **92** | 985 + 211 的简称，**是学历门槛标签**；但在 `92/研究生110-120/小时` 里是**薪酬档位标签**，两者要靠所在字段区分 |
| **982** | **985 的错别字**（T4 真实出现），必须归一到 985 |
| **一本 / 985 / 211** | 学校层次，是并列的「或」关系（满足其一即可），不是「且」 |
| **专职 / 在职** | 老师身份：机构全职老师 / 学校在职教师，通常价格更高 |
| **DSE** | 香港中学文凭考试课程，英语科目的细分方向 |
| **猎德英语** | 猎德是珠江新城地名，科目是英语 |
| **作业辅导** | 不是学科补习，是陪写作业，价格通常偏低 |
| **跑行** | 中介同行之间转单的行为，转单人赚差价 |
| **猎德 / 天河东站 / 蕉门 / 竹料** | 广州地名/地铁站，用于区域提取与通勤计算 |

## 8. 关键设计（动手前必读）

### 8.1 解析按语法维度抽象，不按群抽象

六个群看着是六套模板，拆开只有两个正交变量：

```
① 锚点语法  —— 每群一种，正则池任取其一
② 字段语法  —— 全网通用，一条正则覆盖四种包裹符
```

**判序固定：先锚点，后字段。** 因为 `广州线下: ZX2201#新单` 在语法上完全符合「名称: 值」。

锚点池 6 条：`hashId`（`#1138`）、`cityLabel`（`广州线下: ZX2201#新单`，`#新单` 要剥离为 statusTag 不能混进编号，否则去重失效）、`emojiId`（`🏄 susu2610501`）、`numJiajiao`（`110512号家教`）、`alnumDot`（`ZXGZ20261103.2` / `ZXGZ#20261103.3`）、`labelId`（`家教编号: xxx`）。

字段语法**不是**一条大正则，而是 `readFieldLine()` 的分步判定（字段名可长可短，
`地址` / `对老师要求` 都要支持，一条正则抠不出来）：

1. 抠掉开头的包裹符（`【『「[（(` 之一）
2. 取后面连续的「中文/字母」段，**从长到短**找命中最长的词典别名（否则 `学员地址` 会被 `学员` 抢走）
3. 有左包裹符就必须紧跟配对的右包裹符（`【信息费收取标准】…：` 就是靠这条被挡掉的）
4. 冒号可有可无；**无包裹且无冒号**时只认值以数字/字母/符号开头的紧凑写法（`薪资150-180/h`），
   避免把一句话当成字段
5. `【现阶段成绩】:` 这种空值行必须识别，值记空串

**行内 `#` 不剥离**（`每节课两小时 # 10~12点` 里是时段），只有独立成行的 `# 带相关证书投递` 是噪声。

### 8.2 分档薪水

`一本100/小时，92/研究生110-120/小时` → 存 `salary_tiers` JSON `[{label,min,max,unit}]`。
解析：按 `，` / `；` 切段 → 定位单位标记 → 取单位前**尾部**数字作价格、前缀作档位标签。
标量列 `salary_min/max/unit/salary_hourly` 写**最低档折算值**，供筛选排序，避免每次解析 JSON。

### 8.3 资质匹配三态

八个维度：`gender` / `teacherType` / `schoolTier` / `degree` / `majors` / `certificates` / `languages` / `needsExperience`，另存 `softPrefs` 与 `raw`。

**`schoolTier` 与 `degree` 必须分开**：「985」是学校层次，「硕士」是学位层次。

判定顺序：先剥否定表达（不限/均可/皆可/无需）→ 逐维度比对 → 硬条件不满足即 `不可接` → 软条件不满足降 `存疑` → 全过则 `可接`。**不确定一律落 `存疑`，不落 `不可接`**（漏单不可察觉）。

硬条件：性别明确不符、学校层次无交集、学位要求更高、身份明确限定。
软条件：带「优先/最好/更佳/可协商」的片段；专业、证书、语言默认宽松。

四个坑：`982→985`；`92→985/211`（但薪酬字段里的 92 是档位标签，**要求字段与薪酬字段绝不混扫**）；「优先」≠「必须」；一词两维（`女大学生`、`985研究生`）。

**落地（`profile.ts` + `match/requirements.ts` + `match/match.ts`）：**

- 资质落 `data/profile.json`，**可随时改**，每次请求重新读，不用重启：
  直接编辑文件，或 `PUT /api/profile`（`GET /api/profile` 看当前值）。文件被 `.gitignore` 忽略
- 校验很硬：枚举写错（如 `gender: "男生"`）**直接报错**，不静默跳过 ——
  一个拼错的字段会让整批单子判成可接，比报错危险
- 要求按 `，。；、#` 分句，句中含 `优先/最好/更佳/可协商` 的整句降为软条件；
  `男女不限 / 男女皆可 / 男/女老师均可` 先于性别识别（否则 `男/女` 会被读成两个硬条件）
- 学校层次是**「或」关系**：`一本/985/211` 满足最低的一档即可（211 算通过，只写 `985` 才拦）
- 判定聚合：任一硬条件不符 → `不可接`；否则有任一存疑 → `存疑`；全过 → `可接`
- **经验维度是用户定的策略**：`hasExperience` 默认 `true`，凡「要求有经验」直接放行；
  设为 `false` 才会降 `存疑`。这不是猜，是用户明确说过「不用管」
- 缺资料的维度（`teacherType` / `majorCategory` 等为 `null`）一定落 `存疑`，
  绝不因为「字段没填」就判可接 —— 这条有单独一组断言守着（`match.test.ts` 第 3 节）

### 8.4 通勤

```
CommuteProvider ── AmapProvider
                    ├─ geocode(address)
                    └─ planTransit(origin, dest, departAt) → CommuteOption[]
```

- 一次 transit 调用返回**多套方案**，全部存 `commute_cache.options_json`，卡片显示最快一条
- 缓存键：`起点经纬度4位|终点经纬度4位|mode|出发时刻桶`，**不含用户**，可跨用户复用
- 坐标取 4 位小数（约 10 米），避免同小区异写重复扣配额
- **出发时刻固定「下一个工作日 08:00」并进缓存键**，否则每天算出的数不可比
- 按需计算：**每次 `GET /api/orders` 从全库待算集合里取前 30 条入队**（`db.listCommuteCandidates`）。
  入队源**不得**用当前页 —— 按通勤排序时那一页只有已算完的单子，用它会永远入队 0 条（第 6 节第 22 条）
- 串行队列 400ms 间隔 + 日配额计数 + 失败重试 1 次 + 达上限提示
- 无 key 时通勤列显示「未配置」，其余功能正常

**密钥（还没配 key 的话先看这段）：**

- 控制台「绑定服务」列显示**Web服务**，类型是对的 —— 服务端调 `restapi.amap.com`
  的 POI 搜索与公交路径规划，要的正是这一种
- **key 已配好并验证通过（2026-11-06）**：写在仓库根目录 `.env` 的 `AMAP_KEY`
  （该文件已 gitignore）。实测地理编码 `status=1 OK`，公交路径规划 `status=1 OK`
  且**一次返回 4~5 套方案**（暨南大学石牌校区 → 番禺桥南，最快约 9523 秒、7 元；阶段 5 冒烟实测到 5 套）
- 加载方式：`node --env-file=.env ...`；代码里只读 `process.env.AMAP_KEY`，不落常量
- `Web端(JS API)` 的 key 用不了（那是给浏览器地图组件用的，服务端调用会报鉴权错）
- key 只从 `.env` 的 `AMAP_KEY` 读（`.env` 已在 `.gitignore` 里）；
  **绝不写进代码、文档、提交记录**。Node 24 起可用 `--env-file=.env` 加载
- 该 key 目前**没启用安全密钥/数字签名**（控制台那列是「—」）。本地自用风险不大，
  但建议在高德控制台加**IP 白名单**或开启数字签名；这两件事只能在控制台做，代码侧无法替代
- 测试**用假 provider**，绝不消耗真实配额；真 key 只用于手动跑一次冒烟

**落地（阶段 5 实际实现的形态）：**

```
types.ts    CommuteProvider / CommuteOption / 三类错误（CommuteError、QuotaExceededError、GeocodeMissError）
amap.ts     AmapProvider：/geocode/geo + /direction/transit/integrated（v3，8s 超时）
cache.ts    commute_cache / geo_cache / api_usage 三张表；缓存键、出发锚点、日配额
queue.ts    CommuteQueue：串行 + 400ms 间隔 + 重试 1 次 + 配额撞墙即停
service.ts  编排 + blockedBy 状态；按需入队；geo/plan 双层缓存
```

关键数值与判定：

- 缓存 TTL：方案 30 天、地理编码 90 天；**失败 6 小时**（不落库会被每次刷新重新排队，
  等于每刷一次撞一次同样的错）
- **失败冷却也是 6 小时**：`failed` 的单子在冷却期内不进队列，否则界面每轮询一次就把它捞回来空转一圈
- 日配额上限默认 **300 次 HTTP 调用**（`createDailyQuota` 落 `api_usage` 表，重启不清零）。
  单位是**调用**不是单子：一个 job 最多两次（geocode + plan），所以 300 ≈ 150 单且完全无缓存。
  高德个人档的免费额度是数千级/服务（以控制台为准），300 是主动踩的刹车，不是被卡；
  灌历史单那天用 `.env` 的 **`AMAP_DAILY_LIMIT`** 临时调大（`parseDailyLimit` 校验，写错退回 300）
- 队列间隔 **400ms**（≈2.5 次/秒）：个人 Key QPS 常按 3 次/秒算，300ms 会在某一秒凑出 4 次，
  撞 10004（封停一分钟，表现是「连续失败一阵又自己好了」）
- `status.blockedBy` 三态：`no_key` / `no_origin` / `quota` / `null`。
  界面上的「通勤一片空白」必须能区分这三种原因，否则用户只会以为程序坏了
- `sort=commute` 的 SQL 里硬带 `commute_status='ok'`（红线）；**一单都没算完时接口降级为按时薪排**，
  并用 `sortFallback: true` 明说，绝不把没算的单子塞进「通勤最近」的列表
- 换出发点、或地址被增量补全改动 → `commute_origin_id` / `commute_address` 对不上，判定作废重算
  （多数情况命中缓存，几乎不耗配额）
- 起点**不自动生成**：没有出发点时 `blockedBy='no_origin'`，等用户明确添加（原因见第 6 节第 14 条）

### 8.5 增量补全（应对分次复制）

一条 UPSERT：
- 文本列 `COALESCE(NULLIF(orders.x,''), excluded.x)`
- 数值列 `COALESCE(orders.x, excluded.x)`
- `sent_at` 取更早值，且「精确优先于估算」
- `occurrences + 1`
- **`status` / `starred` / `remark` 一律不动**

落地时补的三条（`db.ts` 的 `UPSERT_SQL`）：

- **JSON 列的空值是 `[]` 不是 `''`**：`subjects` / `subject_tags` / `salary_tiers` 若照 COALESCE 处理，
  第二次导入的 `[]` 会覆盖掉第一次的实值（字符串 `'[]'` 非空）。所以这三列单独用
  `CASE WHEN excluded.x IN ('','[]') THEN orders.x ELSE excluded.x END`
- **置信度只能升不能降**：`low < medium < high`，补全后允许升档，残缺片段不许把 `high` 拉回 `medium`
- **`raw_text` 取更长的那份**：先复制到一半的那段原文不该盖掉后来的完整原文

### 8.6 界面信息层级（阶段 6 的取舍）

卡片三栏：**左=钱、中=单子、右=能不能接**。

```
[130      ]  番禺·桥南  小学 英语 DSE课程            [存疑 2] [已看] [★]
[元/小时   ]  广州市番禺区…                           [28 分钟 · 3 元]
[100-120/h]  初一 上门 每周1次 每次2h #1138  3 小时前
```

几条刻意的决定：

- **时效放在列表行里，不放详情**：好单几小时内被抢，「几小时前」必须在扫一眼时就看到；
  超过 24 小时变红（这种单基本已被接掉）。`sentAt` 为空显示「发送时间未知」，绝不拿导入时间顶替
- **通勤三态各有各的样子**：`28 分钟 · 3 元`（≤45 分绿 / ≤75 分琥珀 / 更久红）、「通勤未算」灰、
  「通勤算不出」红且 `title` 里带原因、「无地址」灰。混成一个横杠，用户会一直等一个不会来的数
- **判定徽标带数字**：`存疑 2` = 有 2 条不通过的维度，`title` 里逐条写。点击展开也能看到「判定依据」
- **换乘方案只在展开时取**：列表 30 条 × 4 套方案是白花请求；展开才 `GET /api/orders/:id/commute`
  （走缓存，不触发高德）
- **算通勤时自动轮询**（3.5s，`quiet` 模式不闪「加载中」）：只要 `commute.busy || queued || enqueued > 0`
  就继续拉；不做 WebSocket —— 为一个十几秒就安静的场景引入长连接不划算
- **空列表要分情况说话**：在通勤排序/通勤上限下为空时，提示「没算完的不参与」，而不是
  「试着放宽时薪」—— 后者会把用户引到错误的配置上去

### 8.7 设置与导入体检（阶段 7 的取舍）

**为什么是右侧抽屉，不是独立设置页**：设置是「顺手改一下、改完继续看单」的附属动作。
独立页面要离开列表、回来还得重新定位，而改资质/加出发点本来就只需要几秒。

**资质改完为什么必须重拉列表**：判定是每次请求现算、不落库（8.3），所以改完资质那一刻，
屏幕上那批 badge 全是旧结论。哪怕只改一个 `hasExperience`，也可能让一批单子从「存疑」变「可接」——
不重拉就是让用户对着过期结论点开单子。

**为什么表单里枚举用分段按钮而不是下拉**：`男/女`、`985/211/一本` 都只有三五个值，
下拉要点两下才看得到全部；分段按钮能一眼看出「我现在是哪一档、还能改成哪几档」，
而资质恰恰是「我离哪些门槛差一档」才需要反复调的。

**为什么「不填」是一个显式选项**：`null` 在判定里意味着「这个维度没资料 → 落存疑」（8.3 的红线）。
如果界面上没有「不填」这一档，用户会随手点一个值来「填满」，把一个本该存疑的维度变成硬条件，
反而更危险。

**导入为什么必须给体检面板而不是一句 toast**：解析的失败面几乎全是**静默**的 ——
编号行没粘上 → 整段变成一个单子、字段互相覆盖；粘的是公告块 → 0 单；
地址被截图裁掉 → 通勤永远「无地址」。这些都不报错，只是结果悄悄变差。
面板把三件事摊开：① 切块依据（锚点种类 × 条数，出现 `none` 就是危险信号）
② 每单缺哪些字段 ③ 置信度与 warnings。缺字段后面那句「再粘一次只补空着的字段」
是配合决策 9（分次复制）说的，否则用户会以为得重粘整条。

**状态条上的按钮为什么值得加**：`no_origin` 是**只有用户能修**的空状态（起点不许猜，第 6 节第 14 条）。
原来只写一句「还没有出发点」，用户还得自己去找设置入口 —— 现在提示条旁边直接给「添加出发点 →」。
同理，资质文件读坏时给一条红条：那种情况下**全表**都会静默变成「存疑」，
看起来完全像「今天没有好单」，不点名就没人会去修 JSON。

**验证方式**：这一轮没引 playwright，用 Edge 的 `--remote-debugging-port` + CDP（Node 24 自带 `WebSocket`）
起无头浏览器，点开抽屉三个页签与导入体检面板各截一张。好处是零新增依赖、不留测试脚本在仓库；
正式化留给阶段 8 的 playwright 端到端。

### 8.8 桌面壳与打包（阶段 8 的取舍）

**壳里为什么只有「起服务 + 开窗口」**：业务逻辑全在本地 HTTP 服务（决策 2），壳里多写一行判断，
浏览器直连 8787 的表现就和桌面版不一样了，两套行为迟早分叉。所以 `main.ts` 不碰数据、不碰解析。

**为什么先把服务端打成单文件（esbuild）**：源码是 TS，靠 Node 原生剥类型跑；打包后既不能赌
Electron 自带的 Node 版本，也不该把 `express`/`cors` 所在的整棵依赖树复制进安装包（workspaces 把
它们提升到了仓库根，路径和平台差异一堆）。打成 `server.mjs` 后安装包里只有这一个文件。

**为什么启动前要实测运行时，而不是硬编码 `ELECTRON_RUN_AS_NODE`**：Electron 内置 Node 是否编进了
`node:sqlite` 取决于构建参数，猜错的后果是「窗口白屏 + 日志正常」。现在探一次：
`-e "require('node:sqlite')"` 能过就用自带运行时（打包版首选，用户无需装 Node），
过不了退回系统 `node`；两个都不行就把真实报错和最后几十行日志弹出来。

**为什么端口被占要让位而不是报错**：8787 上常驻开发期的 `npm run dev` 是最常见的情况，
为此打不开桌面版，用户只会认为程序坏了。换端口对界面零影响（前端全用相对路径 `/api`）。

**为什么退出必须把服务收掉**：留着它就是「下次启动端口被占、库里两个进程同时写」。
冒烟脚本因此专门验一条：`app.close()` 之后 8797/8796 必须能重新 listen。

**为什么打包版要自己铺一份 `.env` 模板**：桌面版没有「项目根目录」，用户无从知道 `AMAP_KEY` 该写在哪；
而没有 key 的表现是通勤一列永远空白。现在首启在 `%APPDATA%\jiajiao\.env` 放好模板（键与注释都写好），
数据落 `%APPDATA%\jiajiao\data`。

**为什么要引 `playwright-core` 而不是 `playwright`**：本机已有 Edge，`channel:'msedge'` 直接驱动它，
省掉 300MB Chromium 下载；真正要验的是界面，不是浏览器内核。端到端**必须用临时库**：
截图里混进真实单子就等于把家长地址/电话写进了图片，而图片会进聊天记录。
